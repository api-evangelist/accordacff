# Accord

> Accord is a revenue excellence platform for B2B sales, onboarding and customer success teams. It turns a company's
> winning sales process into enforceable playbooks, mutual action plans and shared buyer workspaces called Accords.
> Its programmable surface is a single GraphQL endpoint plus a hosted, OAuth-protected MCP server.

Generated by API Evangelist from Accord's own public documentation on 2026-09-06. Accord does not publish an
llms.txt of its own; this file is a third-party summary, not a document Accord serves.

## How to call it

- [GraphQL endpoint](https://api2.inaccord.com/graphql): the entire Accord Developer API. One POST endpoint, no REST,
  no OpenAPI. Authenticate with `Authorization: Bearer YOUR_API_KEY`. Anonymous introspection is refused (HTTP 401).
- [MCP server](https://api.inaccord.com/1/mcp/mcp): hosted, remote, streamable HTTP. OAuth 2.1 + PKCE with dynamic
  client registration; scopes `mcp:read` and `mcp:write`. Read-only in beta. Client config:
  `{"mcpServers":{"accord-mcp":{"type":"http","url":"https://api.inaccord.com/1/mcp/mcp"}}}`.
- [Authentication](https://developers.inaccord.com/authentication): API keys are created by a workspace admin under
  Settings -> Workspace -> API Keys and are shown once. A key is workspace-scoped and obeys the same row-level
  security as an in-app session. Rotate by creating the replacement first, switching clients, then deleting the old key.
- [OAuth authorization server metadata](https://api.inaccord.com/.well-known/oauth-authorization-server)
- [OAuth protected resource metadata](https://api.inaccord.com/.well-known/oauth-protected-resource)

## Core objects

Accord (the shared buyer/seller workspace) has many Stages, which have many Steps. An Accord also has AccordMembers
(each linked to a WorkspaceAccount, which has an Account and a Profile), Resources, Summaries, AccordDomains,
AccordContacts, AccordHealth records and AccordCalendarEvents. CRM mirroring runs through CrmObject and
CrmObjectSync. Ids are prefixed opaque strings (for example `ac_01H...`) and every type also exposes a Relay global
node id via its `*ByNodeId` query.

## Behaviour an agent should know

- No rate limits are published. No `RateLimit-*` or `Retry-After` headers are documented and there is no 429 in the
  published status table. Prefer page sizes of 25-100, which is Accord's own guidance.
- No idempotency mechanism is documented. There is no `Idempotency-Key` header and no client request id, so a retried
  `create*` mutation has no documented protection against creating a duplicate.
- Writes are reversible but the window is not stated. 25 `recover*` mutations pair with the matching `delete*`
  mutations and core objects carry `archivedAt`, but Accord publishes no retention period for recovery.
- Retry only on transient 5xx with exponential backoff. GraphQL `errors[]` are mostly deterministic.
- A response can carry both `data` and `errors`; check both.
